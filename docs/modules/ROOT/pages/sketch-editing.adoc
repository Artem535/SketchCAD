= U04: Constraint-creating snaps, construction geometry, trim/extend
:toc:

Issue: https://github.com/Artem535/SketchCAD/issues/12[#12]. Requirement: S01-EDIT.
Depends on U01 (xref:sketch-viewport.adoc[]), S01 (xref:constraint-solver.adoc[]), U08 (xref:default-dimensions.adoc[]).

Delivered in two parts. Part 1 (this section set) covers the point-on-curve constraint, constraint-creating snaps and
construction geometry. Part 2, trim/extend, is specified in <<part2>> before it is implemented.

Not in this increment: midpoint, tangent-point and perpendicular-foot snaps; snapping to arc end positions (arcs have no
endpoint points in the C01 model); creating constraints while dragging (U03 drags keep the U01 snap behaviour);
"construction excluded from the working profile" beyond drawing and data, since no profile consumer exists before 1.0.

== Point-on-curve constraint (core)
* New kind `kOnCurve` (UI key `on_curve`, "На кривой"): `add_constraint(kOnCurve, point, curve)` where `curve` is a
  line, circle or arc. Rejected (atomically) when the point is an endpoint of that line or the centre of that curve,
  for other entity types, or with the arguments reversed.
* Residuals (hard, mm): line → signed distance of the point from the infinite line, `cross(b − a, p − a) / |b − a|`;
  circle or arc → `|p − c| − r` (an arc is treated as its full circle, as for tangency). A line no longer than the
  length tolerance makes it `kInvalidInput`, as for the other line constraints.
* Diagnostics count it as one row; the independent residual oracle in the tests covers it.

== Snaps (core, `snap`)
* Priority within the snap tolerance: existing point (`kPoint`) → intersection of two curves (`kIntersection`) →
  nearest point on a curve (`kOnCurve`) → grid (`kGrid`). Construction curves take part like normal ones.
* `SnapResult` gains `curves` (the IDs of the one or two curves a `kIntersection`/`kOnCurve` result lies on).
* Intersections: line–line (segments, including endpoints), line–circle/arc, circle/arc–circle/arc; for arcs only
  points within the arc's sweep count; for lines only points on the segment. Tangent or coincident configurations
  without a unique point are ignored.
* On-curve: the nearest point of a line segment, a circle, or an arc within its sweep.
* Grid on curves (`SnapSettings::grid_on_curves`, off by default; user remark after U04 testing): the on-curve
  candidate is the nearest point where the curve crosses a grid line (x or y a multiple of the grid step) within the
  snap tolerance, or the plain nearest point when there is no such crossing. It is still a `kOnCurve` result with the
  same `curves`. Intersections and points keep their priority.

== Snaps that create constraints (core, `ToolSession`)
* A drawing vertex taken from a `kIntersection` or `kOnCurve` snap becomes a new point with one `kOnCurve` per curve,
  added in the same command as the shape (before the automatic dimensions of U08, so redundancy is judged with them).
  A `kPoint` snap keeps reusing the existing point (U01), which already makes the shapes share it.
* Circle and arc centres behave the same (the centre may sit on a curve). An arc's start and end are not points in
  the C01 model, so they get no constraint; rectangle corners do (the corner point at the snapped position).
* Constraints that the solver rejects make the whole command fail as before; nothing partial is committed.
* Automatic dimensions and snapped ends (user remark after U04 testing: "привязывать один конец, размер пусть
  меняется"): a line or polyline segment with an end created from a `kIntersection`/`kOnCurve` snap gets no automatic
  length, and a rectangle with such a corner gets no automatic width and height (its horizontal/vertical constraints
  stay). Moving the curve then stretches the segment while its far end stays. Circle and arc radii are still added.
  A reference dimension (planned U10) is the way to show such a changing length.

== Construction geometry
* Context action `construction` ("Вспомогательная") for selected lines, circles and arcs: toggles their construction
  flag in one undoable command "Construction" (all selected curves get the new state: on if any was off), via
  `ToolSession::toggle_construction()` (false when no curve is selected).
* Construction curves are drawn dashed in `muted` (`construction_path`), not in `geometry_path`; they can be selected,
  constrained, dimensioned and snapped to. Automatic dimensions (U08) are not added to construction shapes; a drawing
  toggle for construction mode is out of scope (toggle after drawing).
* Help (U07) gains `on_curve` and `construction` entries; the snap help mentions intersections and curves.

== Controller and QML
* `snap_kind` adds `intersection` (an × marker) and `curve` (a small ring on the curve).
* `grid_on_curves` property (bool, off by default) maps to the snap setting; the overflow menu has the checkable item
  `gridOnCurvesToggle` ("Сетка на линиях").
* `applicable` includes `on_curve` (point + line/circle/arc in either selection order, after `coincident`; the
  controller passes the point first) and `construction` (any selection containing a curve, last before Delete);
  `apply("construction")` toggles and returns the first selected curve's ID.
* `construction_path` layer, dashed `muted`, 2 px.

== Part 2: trim and extend
Behaviour follows nanoCAD's TRIM and EXTEND (the AutoCAD model), adapted for a tablet as the user agreed:
no edge-selection step (every other line, circle and arc of the sketch is a cutting edge or boundary, as Enter at the
edge prompt in nanoCAD), and two separate tools instead of Shift switching between them. nanoCAD has no
constraints, so the constraint rules below are this project's.

Not in this increment: choosing cutting edges, fence or crossing selection, extending to the extension of a boundary
("edge mode"), trimming points or polylines as a whole, preview of several pieces at once.

=== Core (`sketch_edit.h`, Qt-free)
* `bool trim(Sketch&, EntityId curve, Position at)` and `bool extend(Sketch&, EntityId curve, Position at)` edit the
  sketch in place (used inside one `Document` command); false and unchanged when nothing applies.
* `std::optional<CurvePiece> trim_preview(const Sketch&, EntityId, Position)` and `extend_preview(...)` describe the
  piece that would be removed or added (`CurvePiece`: a segment `a`–`b`, or an arc `center`, `radius`, `start`,
  `sweep`), for display only.
* `pick_curve(const Sketch&, Position, double tolerance)` (`sketch_view.h`): the nearest line, circle or arc, ignoring
  points (ties by lower ID).
* Cuts: the intersections of `curve` with every other curve of the sketch (segments and arc sweeps limited as for the
  U04 intersection snaps, construction curves included). On a line or an arc, cuts at its own ends (within 1e-9 of
  the parameter range) are ignored.

==== Trim
* Line, parameter t of `at` along it: the nearest cut below (t₁) and above (t₂).
  ** No cut: the line is deleted like the select-tool Delete (its constraints, and its end points if nothing else
     uses them, with theirs).
  ** Only t₂ (or only t₁): the piece from the start to t₂ (or from t₁ to the end) is removed: a new point at the cut
     becomes the line's start (or end).
  ** Both: the middle piece is removed and the line splits: the original line (same ID) keeps start → t₁, a new line
     runs t₂ → the old end.
* Arc: the same in angle along its sweep (start → end); a split keeps the original arc (same ID) for the first piece
  and adds a new arc on the same centre point with `kEqual` to the original, so both stay on one circle.
* Circle: the cut angles around it; fewer than two distinct cuts → no cut leaves the circle deleted (as for a line),
  one cut rejects (false, unchanged). Otherwise the piece between the nearest cuts on either side of `at` is removed and
  the circle becomes an arc with the same ID, centre point, radius and construction flag, from the cut after the piece
  to the cut before it (counter-clockwise); `Sketch::circle_to_arc(id, start, sweep)` does that in place.
* Constraints:
  ** a new cut end gets `kOnCurve` on each cutting curve through it (one, or two at a crossing of cutters), so it stays
     on the edge it was cut at, like a U04 snap;
  ** constraints on the trimmed curve stay on the piece that keeps its ID; a driving `kLength` on it takes the new
     length; radii and reference dimensions are unchanged (references show the new measurement);
  ** an end point no longer used by any entity is erased with its constraints; points kept on the curve by `kOnCurve`
     keep their constraint (it treats the curve as infinite or as its full circle);
  ** the result must solve (`kSolved` with the commit step), otherwise the whole command fails and nothing changes.

==== Extend
* Line: the end nearer to `at` moves along the line, beyond that end, to the nearest intersection with another curve
  (its segment or sweep). The end point keeps its ID and gets `kOnCurve` on the boundary, and loses its `kOnCurve`
  on curves it leaves (an earlier boundary), which would otherwise hold it back; a driving `kLength` takes the new
  length. Rejected (false) when nothing lies ahead or when the end point is also used by another entity (moving it
  would drag that geometry along).
* Arc: the end nearer to `at` grows along the circle (sweep below a full turn) to the nearest intersection ahead;
  arc ends are not points, so nothing is constrained there.
* As for trim, the result must solve.

=== Tools (`ToolSession`), controller and QML
* `Tool::kTrim` ("Обрезать", icon `trim.svg`) and `Tool::kExtend` ("Удлинить", icon `extend.svg`), names `trim` and
  `extend`, rail buttons `tool_trim`, `tool_extend` after "Размер". A tap picks the curve with `pick_curve` and runs
  `trim` or `extend` as one command "Trim" or "Extend" (one undo step); a tap that changes nothing adds no history.
  The tool stays active for the next tap.
* Hover shows the piece that a tap would remove (trim, drawn in `err`) or add (extend, drawn in `primary`, dashed) as
  `edit_preview_path`.
* The tool rail scrolls vertically when its buttons do not fit the window height.
* Help (U07) gains `trim` and `extend`.

=== Acceptance / test cases (part 2)
Core (`sketch_edit_test`):

* a line crossed by two lines: a tap between the crossings splits it; both pieces end exactly on the cutters with one
  `kOnCurve` each; the original ID keeps the first piece; a driving length on it takes the new length; the sketch
  solves;
* a tap on the end piece beyond the last crossing moves that end to the crossing and erases the old end point when
  unused; a corner point shared with another line stays;
* a line without crossings is deleted with its unshared points and constraints;
* a circle crossed by two lines becomes an arc with the same ID and radius, without the tapped piece; with one
  crossing it is unchanged (false);
* an arc crossed twice splits into two arcs with `kEqual`;
* extend: a line extends to the nearest line or circle ahead (end point ID kept, `kOnCurve` added); extending again
  moves on to the next boundary and drops the first one's `kOnCurve`; nothing ahead or a shared end → false and
  unchanged; an arc extends to a line ahead;
* `trim_preview` / `extend_preview` describe exactly the removed / added piece; `pick_curve` ignores points.

`sketch_tool_test`: a trim tap is one "Trim" undo step and Undo restores the sketch; a tap on empty space or with
nothing to do adds no history; extend likewise ("Extend").
Qt (`sketch_controller_test`): `set_tool("trim")`, hover over a piece gives a non-empty `edit_preview_path`, a tap
trims; `extend` likewise.
QML (`qml_test`): draw two crossing lines, choose `tool_trim`, tap one line's end piece, the line now ends at the
crossing; screenshot `sketch_u04_trim.png`; the rail shows `tool_extend` (scrolling if needed).
Desktop only.
