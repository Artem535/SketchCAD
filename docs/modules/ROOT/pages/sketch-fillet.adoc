= U12: Sketch fillet
:toc:

Issue: https://github.com/Artem535/SketchCAD/issues/59[#59].

User approved a line-line sketch fillet on 31 October 2026, with the same staged tablet interaction as
xref:sketch-chamfer.adoc[]. The latest instruction restores fillet before vertex merging and the 3D milestone.

== Behavior and limits

Select “Скруглить”, pick two distinct lines sharing a topological corner, adjust the radius via a large offset grip
or the on-canvas radius dimension/keypad, inspect a dashed tangent arc, then confirm with Done/Enter. Until confirmation
no document geometry, IDs, constraints, revision or history change. Esc/Cancel, reset, tool switch and Undo/Redo clear
staging. Invalid second picks retain the first. A numerically overlarge radius retains the pair and input control,
clears preview and disables confirmation so it can be corrected. Default radius 2 mm, retained independently from
chamfer setback. Grip works with mouse/stylus/finger including finger-pan mode; it must not pan the view. Release
never commits. A successful fillet is one transaction and one Undo step. Solver rejection retains a retryable pair.

First increment: one shared endpoint of exactly two straight lines, with no third geometry using it. No line-arc,
arc-arc or disconnected crossing fillets, automatic whole-polyline rounding or 3D body-edge fillets. Reject collinear
lines, invalid/nonfinite radius, vanishing or reversed shortened lines and either selected line in an equal-length
constraint. The grip uses the same 56 px target/64 px midpoint offset and full-vector projection as chamfer.

== Geometry and constraints

For corner P, incident unit directions u1,u2 and interior angle theta in (0, pi), use setback
`t = r * cot(theta/2)` and centre `C = P + (u1 + u2) * r / abs(cross(u1,u2))`.
New contacts are `P + t*u1` and `P + t*u2`; the counter-clockwise minor arc spans `pi-theta` between the contacts.
Keep original line IDs and the old corner as construction virtual sharp with two on-curve constraints. Preserve all
constraints on it. Convert each incident line length to an overall point distance to the virtual sharp, preserving
constraint ID/value/reference state and clearing manual placement, exactly as chamfer. Both construction input lines
produce a construction fillet; mixed inputs produce normal geometry. Add one driving radius dimension regardless of
automatic dimensions setting. Existing constraints on input lines remain. Degrees of freedom must remain unchanged.

The model needs endpoint-aware tangency so radius/angle/overall-size changes preserve connected contact points.
Add `ConstraintKind::kTangentStart` and `kTangentEnd`: first=line, second=arc, side=+1 selects the line start and -1
selects its end. `Sketch::add_arc_tangency(kind,line,arc,point)` validates the explicit endpoint and captures side.
Each has two length residuals: signed centre-to-contact projection onto the oriented line normal minus radius,
with the normal branch captured in `internal`, and radial vector dot the line unit direction. The captured normal
branch, together with preserving the minor/major sweep branch of a doubly bound arc, prevents oversized radius
edits from silently reversing shortened lines or escaping through a major arc. Such edits fail transactionally.
This fixes contact position and tangent direction at first order, avoiding the singular combination of generic
line-circle tangency plus point-on-circle at the contact. Arc start/sweep are derived from its bound contacts after
solving; unconstrained/ordinary arcs retain their existing angle behavior. Invalid/coincident contacts and invalid
sweeps fail transactionally. `Sketch::update_line` and `Sketch::update_arc` reject endpoint/centre updates that would
violate endpoint-tangency or on-curve reference invariants (centre on a bound line endpoint, two bindings of one arc
sharing the same contact point, or an on-curve point becoming a defining point), keeping live sketches snapshot-valid.
Trim and extend respect bound arc contacts: a line endpoint or arc end bound by `kTangentStart`/`kTangentEnd` is not a
free end for `extend`; trimming away a bound line end or bound arc end detaches that endpoint-tangency relation cleanly,
and splitting a bound line or arc in the middle keeps the endpoint-tangency relation on the piece that retains the bound
end. New relations participate in diagnosis, drag, validation and project round-trip.
Persistence adds tags `tangent_start`, `tangent_end` in schema version 2. Writers use v2 when these bindings exist;
ordinary sketches continue to write v1. Readers accept v1 and v2, but v1 must reject v2-only tags; future versions
fail explicitly. Old readers report unsupported version rather than lose bindings. Stored arc endpoint angles must
match contact points; malformed cached angles are rejected, never silently repaired by file loading. No existing
entity wire shape changes or OCCT/Qt core dependencies.

== Acceptance

A dimensioned rectangle becomes four shortened sides and one tangent arc after a corner fillet. A radius edit and
an overall width/height edit leave arc contacts coincident with their actual line ends and perpendicular to each
radial vector. Radius equals the driving value; the old corner/line/constraint IDs and overall dimensions remain.
Undo/Redo restore exact snapshots; file save/open preserves the result and subsequent radius editing. Rejected
operations leave geometry/history untouched. Tests include 60, 90 and 120 degree corners, both selection orders,
limits and nonfinite data, and synthetic input without making physical-tablet claims.
