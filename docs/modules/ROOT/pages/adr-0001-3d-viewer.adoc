== Контекст

Нужен интерактивный 3D-вид для деталей и сборок на Android-планшете ARM64, Linux и Windows x86-64:
вращение/сдвиг/масштаб касанием, стилусом и мышью; выбор граней, рёбер и вершин B-rep; режимы
«тело», «тело с рёбрами», «каркас»; секущие плоскости; гизмо осей и манипуляторы поверх модели.
Для чертежей нужны проекции с удалением невидимых линий. Интерфейс остаётся на Qt Quick/QML.

Ограничения:

* Лицензия проекта — source-available с запретом сторонней продажи (xref:licensing.adoc[]).
  Зависимости не могут требовать GPL/AGPL для всего приложения.
* Ядро модели уже планируется на OCCT; эскиз и решатель остаются независимыми от Qt и OCCT.
* Android входит в обязательные платформы с 0.1; на Android Qt Quick по умолчанию рисует через OpenGL ES.

== Решение (предлагаемое)

Использовать вариант A: просмотрщик OCCT (V3d/AIS) рендерит 3D в контексте OpenGL/OpenGL ES окна Qt Quick;
интерфейс QML рисуется поверх. Qt Quick принудительно использует OpenGL-бэкенд RHI
(`QQuickWindow::setGraphicsApi(QSGRendererInterface::OpenGL)`), чтобы OCCT и сцена QML делили один контекст.

Граница модулей: 3D-вид — отдельный модуль приложения (viewer adapter) с узким интерфейсом
«показать форму, камера, выбор, режимы отображения». Ни core модели, ни решатель не зависят от него.
Это сохраняет возможность заменить A на B без изменения модели.

Запасной вариант — B. Переход к B выполняется, если SPK-3D не проходит или если требования к производительности
на Android не выполняются с OpenGL ES (см. раздел про Vulkan).

== Vulkan или OpenGL ES

Google называет Vulkan основным низкоуровневым API Android; OpenGL ES поддерживается, но не развивается.
Все 64-битные устройства с Android 10+ поддерживают Vulkan 1.1. С Android 15 OpenGL ES может работать
поверх Vulkan через ANGLE, и Google планирует со временем поставлять OpenGL ES только через ANGLE.

Выводы для SketchCAD:

* OCCT не имеет Vulkan-драйвера; поддержка Vulkan у OCCT остаётся долгосрочным планом.
  Вариант A означает OpenGL ES на Android.
* Преимущество Vulkan — меньшая нагрузка CPU на вызовы отрисовки. Для CAD это важно на больших сборках
  с множеством отдельных объектов; для одной детали узкое место обычно не в API.
  Насколько оно проявится на ориентире «100 уникальных / 500 компонентов», покажет только замер.
* OpenGL ES не станет недоступным: на новых устройствах он будет идти через ANGLE поверх Vulkan.
  Это риск по производительности и драйверам, а не по наличию API — проверяется в SPK-3D.
* Путь к Vulkan сохраняется через вариант B (Qt RHI выбирает Vulkan на Android) или через будущий
  Vulkan-драйвер OCCT. Решение о переходе — отдельный ADR по данным замеров.

== SPK-3D: spike встраивания OCCT viewer

Цель — получить измеренные данные для принятия или отклонения варианта A. Spike — исследовательский код,
не часть 0.1 и не обещание поддержки 3D. Длительность ограничивается решением пользователя.

=== Объём

* Сборка OCCT и Qt 6 под Android ARM64 и Linux x86-64 через vcpkg/CMake; версии записываются.
* Минимальное приложение: QML-оболочка из макета (панель инструментов, гизмо осей, кнопки сдвига/масштаба)
  поверх окна OCCT; загрузка детали «Крепёжная пластина» и синтетической сборки 500 экземпляров / 100 уникальных.
* Перенос идей примера OCCT `samples/qt/AndroidQt` на Qt 6, без копирования кода без проверки лицензии.

=== Критерии приёмки

[cols="1,4",options="header"]
|===
|ID |Критерий
|SPK-3D-01 |APK собирается из чистого checkout по записанным командам; Linux-сборка тем же CMake.
|SPK-3D-02 |На реальном Android-планшете OCCT рисует модель, QML-элементы видимы и кликабельны поверх неё, без мерцания и рассинхронизации кадров.
|SPK-3D-03 |Один палец вращает, два пальца сдвигают и масштабируют; мышь и колесо — на Linux. Стилус и палец различаются в Qt pointer handlers.
|SPK-3D-04 |Касание выбирает грань, ребро и вершину B-rep; выбранная сущность возвращается как ссылка OCCT, подсветка видна.
|SPK-3D-05 |Работают режимы «тело», «тело с рёбрами», «каркас» и одна секущая плоскость.
|SPK-3D-06 |Сворачивание/возврат приложения, поворот экрана и смена DPI не ломают вид: потеря GL-контекста обрабатывается без падения.
|SPK-3D-07 |Измерены: время до первого кадра, время кадра при вращении (медиана и p95) для детали и сборки, задержка выбора, память. На планшете и на Linux. Отдельно — устройство с ANGLE, если доступно.
|SPK-3D-08 |Записаны ограничения, найденные проблемы драйверов и обязательства лицензий OCCT/Qt для поставки.
|===

Численные пороги заранее не задаются (xref:roadmap.adoc[] запрещает выдумывать budgets):
пользователь принимает или отклоняет результат по замерам SPK-3D-07.

=== Результат

Evidence, замеры, снимки/видео и ограничения записываются в GitHub issue spike'а.
По итогам этот ADR переходит в статус «Принято» или «Отклонено»; при отклонении открывается spike варианта B.

== Последствия

* 3D-вид зависит от OpenGL ES на Android; Vulkan откладывается до данных замеров.
* Qt Quick в окне с 3D работает на OpenGL-бэкенде; Vulkan-бэкенд Qt Quick в этом окне не используется.
* Код просмотра изолирован адаптером — замена на вариант B затрагивает только его.
* Qt Quick 3D в проект не добавляется; модель лицензии менять не требуется.
* HLR для чертежей берётся из OCCT независимо от выбора рендерера.
