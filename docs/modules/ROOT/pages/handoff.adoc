== Обязательный порядок работы

Из `AGENTS.md`:

. Спецификация в Antora: поведение, ограничения, критерии приёмки. Страница лежит в `docs/modules/ROOT/pages/*.adoc`,
  на неё ссылаются `nav.adoc` и раздел в `backlog-0.1.adoc`.
. Issue со ссылкой на спецификацию.
. Метки: тип (`enhancement`, `bug`, `documentation`), подсистема (`area:*`) и `status:ready`.
. Тесты и зафиксированное ожидаемое падение (RED) до реализации.
. Реализация, полный прогон проверок, PR со ссылкой на issue через `Closes #N` в описании.

Практика, сложившаяся в сессиях:

* *Коммиты и PR*
  ** В коммитах пишем `Refs #N`, в PR — `Closes #N`.
  ** Если на одну issue приходится несколько PR (U04), в первом пишем `Refs`, и issue остаётся открытой до последнего.
  ** Стековый PR после слияния базы перенацеливается на `main`: `gh pr edit N --base main`.
* *Свидетельства проверки*
  ** RED/GREEN, окружение и найденные дефекты тестов записываются в раздел «Execution record» спецификации и в
     комментарий к issue.
  ** Метка меняется `status:ready` → `status:review` при открытии PR.
  ** Логи кладутся в `build/issueN-red.log`, `build/issueN-green.log`, `build/issueN-werror.log`
     (`build/` не в git).
* *Дефект теста* исправляем в тесте, не меняя проверяемого ожидания, и пишем об этом в execution record.
  Тест, добавленный после реализации, помечаем как «не виден падающим», если его RED не проверяли.
  Удобный способ проверить RED задним числом — временно откатить исправление (`git stash push <файл>`).
* *Перед «готово»*: полный CTest в обеих сборках (<<build>>) и осмотр скриншота QML-теста.
* *Подписи*
  ** Коммиты заканчиваются строкой `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  ** Описание PR заканчивается строкой `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
* *Слияние*
  ** Только по явному слову пользователя («сливай» / «смержи»).
  ** Слова «норм», «работает», «выглядит хорошо» — это не разрешение. Классификатор прав
     такое слияние блокирует, поэтому надо спросить.
  ** Перед слиянием нужен зелёный CI.
  ** Если PR прогонялся до того, как в `main` попали другие изменения в тех же файлах, проверить сочетание локально:
     временная ветка от `main` + `git merge` PR + полный CTest.
  ** Сливать merge commit: `gh pr merge N --merge`. Auto-merge в репозитории запрещён.
* *Запрещено*: утверждать поддержку Android по desktop-тестам, выбирать лицензию, добавлять платежи.

== Окружение, сборка и проверки

Среда:

* vcpkg в `/home/a.durynin/Soft/vcpkg` (Ceres 2.2, Eigen, GoogleTest).
* CI — Qt 6.12 на Ubuntu 24.04 (`.github/workflows/ci.yml`: desktop build + CTest и сборка Antora).

Каталоги сборки:

* `build/ubuntu` — Release.
* `build/werror` — Debug с `-Wall -Wextra -Werror -fsanitize=address,undefined`.
* `build/vcpkg` устарел, не использовать.

[source,shell]
----
cmake --build build/ubuntu -j 8 && ctest --test-dir build/ubuntu
cmake --build build/werror -j 8 && ASAN_OPTIONS=detect_leaks=0 ctest --test-dir build/werror
./build/ubuntu/sketchcad          # приложение; --smoke, --screenshot <файл>
npm run docs                      # Antora читает Git HEAD: сначала коммит
----

При добавлении нового файла `src/*.cpp` или нового теста нужен `cmake -S . -B build/<dir>` для обеих сборок.
На срезе (ветка `feature/12-trim-extend`): 189/189 CTest в обеих сборках.

Известные особенности:

* *Тесты под ASan.* LeakSanitizer ругается только на системные glib/fontconfig/Qt при выходе, поэтому для
  Qt-тестов `detect_leaks=0`.
* *`-Werror`.*
  ** `-Wmissing-field-initializers` срабатывает на агрегатную инициализацию без члена, у которого нет NSDMI.
     Новые поля структур объявлять со значением по умолчанию (`= {}`, `= std::nullopt`).
  ** `Constraint c{};` вместо `Constraint c{0, kind, ...}`.
* *Запуск с хоста.* `host-spawn <команда>` запускает программу на хосте. LibreCAD 2.2.1 стоит на хосте; рендер DXF:
  `host-spawn librecad dxf2png -o out.png file.dxf`. Файлы сравнения с LibreCAD лежат в `~/sketchcad-compare/`.
* *Push.* `SSH_ASKPASS= GIT_ASKPASS= git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push ...`.
  После `rebase` своей ветки — `--force-with-lease`.
* *Мусор в выводе.* `Gtk-Message: Failed to load module ...` при запуске — системная тема, не ошибка.
* *Отладка QML.* `console.log` фильтруется — использовать `console.warn` / `qWarning()`.
* *Тема в offscreen.* Offscreen-платформа отдаёт тёмную схему хоста; QML-тесты задают тему явно (`darkTheme`).

== Продукт и рамки

SketchCAD — параметрическая механическая CAD для инженера и небольшого бюро.

* Основной сценарий — Android-планшет; Linux и Windows обязательны. Работает offline, без аккаунта, RU/EN.
* 0.1 — самостоятельный 2D-эскизёр. 1.0 — детали, сборки, чертежи (OCCT), обмен данными, Python-макросы.

|Вид (мм ↔ px), `pick`, `pick_curve`. Привязки: точка → пересечение → кривая → сетка; опция «Сетка на линиях».

|xref:sketch-viewport.adoc[], xref:sketch-editing.adoc[]

|`sketch_tool`
|`ToolSession` — инструменты:
* выбор, линия, ломаная, прямоугольник, окружность, дуга;

* «Обрезать» и «Удлинить» (U04, часть 2).

Режимы рисования:
* живые и автоматические размеры, ввод числа при рисовании (U08);
* вершина, взятая с привязки к кривой, получает `kOnCurve`, и у такого отрезка нет авторазмера длины.
|xref:default-dimensions.adoc[], xref:reference-dimensions.adoc[]

|`dimension_layout`
|Раскладка размеров по ЕСКД в экранных px (ADR-0004). Сторона размера — от центра связной группы точек (#41).
Ручное положение — U09. `dimension_placement_at` — общая функция для переноса размера и для инструмента «Размер».
|xref:dimension-style.adoc[], xref:dimension-placement.adoc[]

|`sketch_edit`
|`trim`, `extend` и их предпросмотр в духе nanoCAD. Окружность становится дугой на месте (`circle_to_arc`, тот же ID).
|xref:sketch-editing.adoc[] (часть 2)

== Уроки и ловушки

* *Живые подписи U08 перехватывают нажатия.*
  ** Канвас отдаёт нажатие на живую подпись ей самой, чтобы по ней можно было кликнуть и ввести число.
  ** У инструмента, где предпросмотр едет за курсором (U10), это ломает размещение. Там правило отключено.
* *Привязка к кривым во время перетаскивания* уводила точку на соседнюю линию. Перетаскивание привязывается только к
  точкам и сетке (`SnapSettings::curves = false`).
* *Мягкая фаза перетаскивания* с якобиевым масштабированием Ceres ползла, когда точка на окружности лежала почти
  на направлении движения. Помогло равномерное демпфирование (#48). Тесты двигают мышь шагами по 0,25 мм, как
  настоящий указатель.
* *Решатель минимизирует сдвиг всего остального.* Поэтому точки на перемещаемой кривой надо явно делать целями,
  иначе они соскальзывают по ней.
* *Ревизия документа после Undo* возвращается к ревизии восстановленного состояния, а не растёт.
* *Длинная левая панель* перестала помещаться в 800 px; теперь прокручиваются только инструменты.
* *Qt Test.* Использовать `QTest::mouseClick` и `qWaitForPolish`. Закрытый `Popup` уходит из дерева.
  Вспомогательные функции не класть в `private slots`.
* *Ceres.* Один parameter block нельзя дважды передать в один residual. Сходимость ≠ выполнение ограничений.
  На задаче без residual-блоков Ceres падает.

== Ограничения и долг

* Android, стилус, пинч и производительность на устройстве не проверены (P01).
* Переводов RU/EN нет; строки обёрнуты в `qsTr` (R01).
* Сохранения нет: всё теряется при закрытии (F01/F02).
* `kOnCurve` и касание считают дугу полной окружностью, а линию — бесконечной.
* У концов дуг нет точек: к ним нельзя привязать ограничение.
* Справочный угол и расстояние от точки до линии не поддержаны.
* Пересекающиеся размеры не разносятся автоматически (их двигают вручную, U09).
