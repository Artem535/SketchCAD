Среда: Ubuntu 26.04 в контейнере (toolbox) на хосте Fedora; Wayland-сессия; GCC 15.2, CMake 4.2.3, системный Qt 6.10.2,

* `build/werror` — Debug с `-Wall -Wextra -Werror -Wno-self-move -fsanitize=address,undefined`
  (`-Wno-self-move` нужен для намеренного теста self-move в `sketch_test`).
* `build/vcpkg` — устаревшая конфигурация прежней машины (Fedora); не трогать и не использовать.

[source,shell]
----

cmake --build build/ubuntu -j 8

./build/ubuntu/sketchcad   # приложение; --smoke, --screenshot <файл>

Состояние на срезе (ветка `docs/handoff` = `fix/degenerate-geometry` + этот документ): 106/106 CTest в обеих сборках.

Известные особенности окружения:

* LeakSanitizer сообщает утечки только в системных fontconfig/pango/glib при запуске Qt; поэтому
  `detect_leaks=0` для Qt-тестов. Core-тесты чисты и с LeakSanitizer.
* CMake печатает предупреждения «qml plugin ... link target does not exist» — особенность упаковки Qt в Ubuntu,
  безвредна для динамического Qt.
* `clang-format` не установлен; длину строк (80) проверять вручную.
* `Gtk-Message: Failed to load module ...` при запуске приложения — системная тема, не ошибка.
* Push: `ksshaskpass` отсутствует, поэтому разовым helper'ом
  `SSH_ASKPASS= GIT_ASKPASS= git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push ...`.
  У токена `gh` есть scope `workflow`. Глобальный git config не менять.
* В репозитории запрещён auto-merge (настройка GitHub); сливать вручную после зелёного CI.

== Архитектура (что есть в коде)

Слои: `include/sketchcad` + `src` → `sketchcad_core` (без Qt и OCCT, Ceres/Eigen — приватно); `app/` → Qt-слой.

[cols="1,3,1"]
|===
|Модуль |Суть |Контракт

|`sketch.h/.cpp`
|`Sketch`: точки, линии, окружности, дуги со стабильными `EntityId` (uint64, не переиспользуются, watermark сохраняется
при присваивании снимков); ограничения и размеры хранятся здесь же и используют тот же аллокатор ID.
Сущность, на которую ссылается другая сущность или ограничение, не удаляется (без неявного каскада).
Равенство `Sketch` — по содержимому (сущности + ограничения), не по аллокатору.
|xref:sketch-model.adoc[]

|`document.h/.cpp`
|`Document`: атомарные команды на рабочей копии, commit step (сюда ставится решатель), снимковые Undo/Redo,
жесты (перетаскивание = один шаг), dirty относительно сохранённой ревизии.
|xref:document-commands.adoc[]

|`sketch_view.h/.cpp`, `sketch_tool.h/.cpp`
|`ViewTransform` (мм, Y вверх ↔ px, Y вниз), `pick`, простая привязка к сетке и точкам, шаг сетки 1-2-5;
`ToolSession`: инструменты выбор/линия/ломаная/прямоугольник/окружность/дуга, выбор до двух объектов
(касание добавляет, пустое место сбрасывает), удаление выбранного одной командой с каскадом ограничений.
|xref:sketch-viewport.adoc[]

|`constraint.h`, `solver.h`, `constraint_solver.cpp`, `src/solver_problem.h`
|Ограничения: совпадение, горизонт./вертик., параллельность, перпендикулярность, касание, равенство, фиксация.
`solve()`: одна задача Ceres (LM, dense QR) из жёстких residual; после решения каждый residual проверяется
(1e-7 мм, 1e-9 рад); запись только при `kSolved`. Статусы: `kInvalidInput`, `kUnsatisfied` (конфликт),
`kNumericalFailure`, `kDegenerate` (решение схлопывает линию/радиус; перед отказом одна повторная попытка с
удержанием размеров и поворотом на 1e-3 рад). `solver_step()` — commit step для `Document`.
`solver_problem.h` — внутренний общий для решателя и диагностики заголовок.
|xref:constraint-solver.adoc[]

|размеры в `Sketch` и `solver.h`
|`kLength`, `kDistance` (точка–точка; точка–линия со стороной), `kAngle` (неориентированный, радианы, остаток через
½·atan2(sin 2φ, cos 2φ)), `kRadius`; `add_dimension`/`set_dimension`/`measure`.
Прототип `Rectangle` (issue #1) удалён, его сценарий — `Dimensions.PrototypeRectangleScenario`.
|xref:dimensions.adoc[]

|`diagnostics.h`, `constraint_diagnostics.cpp`
|`diagnose()`: решает копию, якобиан из той же задачи Ceres, нормализация строк, ранг по SVD с серой зоной
(→ «неизвестно»), зависимые ограничения через левое нуль-пространство (не минимальный набор), DOF = параметры − ранг.
|xref:diagnostics.adoc[], xref:adr-0003-dof-diagnostics.adoc[ADR-0003]

|`app/sketch_controller.*`
|`SketchController` — мост в QML: геометрия как SVG-пути в px, решатель как commit step, `applicable`/`apply`
(только допустимые действия; вырождающие не предлагаются), список ограничений, кешированная диагностика,
подсветка конфликта отклонённой команды, размеры (углы в градусах), ключи сообщений в `message`.
|xref:constraint-ui.adoc[]

|`app/*.qml`
|`Main.qml` — оболочка Material (рейка инструментов, контекстная панель действий, чип DOF, зум, горячие клавиши);
`SketchViewport.qml` — Qt Quick Shapes `CurveRenderer` (ADR-0002) и обработчики ввода; `DimensionEditor.qml` —
редактор размера с экранной клавиатурой; `ConstraintPanel.qml` — список ограничений.
|xref:adr-0002-tablet-ui.adoc[ADR-0002]

== Уроки и ловушки этой сессии

* *Wayland и тачпад*: тачпад приходит как `PointerDevice.TouchPad`; обработчик инструмента должен принимать все
  устройства (тач-экран — только при «Палец рисует»). Под X11/xdotool это не воспроизводится.
* *Qt Test*: синтетические `QMouseEvent` через `sendEvent` не активируют `PointHandler` — использовать
  `QTest::mouseClick`; перед кликом ждать `QQuickTest::qWaitForPolish`; закрытый `Popup` уходит из дерева сцены
  (`item()` вернёт null); снимок сразу после открытия попапа ловит анимацию появления — подождать ~400 мс.
  Вспомогательные функции не класть в `private slots` (Qt Test запустит их как тесты).
* *Material*: фоны `Pane`/`Popup` в этой оболочке рисуются прозрачными — задавать `background` явно.
* *Ceres*: один и тот же parameter block нельзя дважды передать в один residual (линии с общей точкой) —
  поэтому `DynamicAutoDiffCostFunction` с дедупликацией блоков. Сходимость ≠ выполнение: всегда пересчитывать
  residual. Симметричный старт (строго горизонтальная линия + «вертикально») не имеет градиента поперёк — нужен
  детерминированный малый поворот.
* *Остаток угла* через atan2 удвоенного угла не имеет стационарной точки при перпендикулярном старте
  (в отличие от sin/cos).
* Хелпер теста, возвращающий результат откатанной команды, даёт ложные провалы — проверять `execute()`.

== Ограничения и долг

* Android, планшет, стилус, пинч и производительность на устройстве не проверены (P01).
* RU/EN: строки обёрнуты в `qsTr`, переводов и проверки раскладки EN нет (R01).
* Касание с дугой считается по полной окружности; углы дуг не являются переменными решателя.
* Пути `kIllConditioned`, `kTooLarge`, `kNumericalFailure` реализованы, но тестами не достигаются.
* Нет значков ограничений на холсте, нет размерных линий (сейчас — подписи-«таблетки»).
* `npm` ранее сообщал уязвимости инструментов документации; аудит не проводился.
* Опубликованный ранее на ChatGPT Sites макет 1.0 (`design/sketchcad-1.0.html`) — артефакт прошлого агента;
  актуальные макеты планшета — `design/sketchcad-tablet*.html` (эскиз, 3D, сборка, чертёж).
