= U11: Chamfer tool
:toc:

Issue: https://github.com/Artem535/SketchCAD/issues/56[#56]. Requirement: S01-EDIT. Depends on U04 part 2 (xref:sketch-editing.adoc[], trim/extend),
U08 (xref:default-dimensions.adoc[], dynamic input).

Origin: the user asked for chamfers in the sketcher. This is the 2D sketch chamfer at a corner between two lines, as
nanoCAD's CHAMFER with equal distances; the 3D chamfer of a body edge stays in 1.0 (R10-FEATURE, after OCCT).

Not in this increment: unequal distances or distance + angle, chamfers between a line and an arc, several corners in
one tap (a whole polyline or rectangle), fillets.

== Core (`sketch_edit.h`, Qt-free)
* `bool chamfer(Sketch&, EntityId corner, double distance)` edits the sketch in place (used inside one `Document`
  command); false and unchanged when nothing applies.
* `std::optional<CurvePiece> chamfer_preview(const Sketch&, EntityId corner, double distance)`: the chamfer segment
  that `chamfer` would add, for display only.
* `pick_corner(const Sketch&, Position, double tolerance)` (`sketch_view.h`): the nearest point within the tolerance
  that is an end of exactly two lines (ties by lower ID); nullopt otherwise.
* `ChamferStatus chamfer_status(const Sketch&, EntityId corner, double distance)` shares validation with preview and
  editing: `kReady`, `kNotCorner`, `kInvalidDistance`, `kTooLong`, `kCollinear`, `kEqualLength`.
  Picking tests topology only, so a collinear or equal-constrained corner can still explain its rejection.
  Non-finite cursor coordinates or tolerance, and negative tolerance, pick nothing.

=== Geometry
* The corner `P` is an end of exactly two lines, `L1` (from `P` to its other end `A`) and `L2` (from `P` to `B`).
  Arcs and circles do not count; a point used by any other entity (a third line, a circle centre) is not a corner.
* With unit directions `u1 = (A − P) / |A − P|` and `u2 = (B − P) / |B − P|`, two new points are created at
  `P1 = P + distance · u1` and `P2 = P + distance · u2`, and a new line `P1 → P2` (the chamfer) is added. It is a
  construction line when both `L1` and `L2` are construction lines, a normal line otherwise.
* `L1` and `L2` keep their IDs; their end at `P` is replaced by `P1` and `P2`.
* `P` stays as the *virtual sharp* (the user's choice, as in SolidWorks): same ID and position, now a construction
  point that ends no line, drawn like other construction geometry. It marks the former corner, so dimensions and
  relations to the corner survive the chamfer.
* Rejected (false, unchanged): `distance` not finite or ≤ the length tolerance; `distance` ≥ the length of `L1` or of
  `L2` minus the length tolerance (the line would vanish or flip); `L1` and `L2` collinear (angle between them within
  the angle tolerance of 0° or 180°).

=== Constraints
* The virtual sharp `P` gets `kOnCurve` on `L1` and on `L2` (each treats its line as infinite), so it stays at the
  intersection of the two lines. All constraints already on `P` stay (fix, coincident, point–point and point–line
  distances, `kOnCurve` on other curves).
* The chamfer is parametric: two driving point–point `kDistance` dimensions, `P`–`P1` and `P`–`P2`, both equal to
  `distance`, are always added (whether automatic dimensions are on or off). Editing one of them later moves that end
  of the chamfer; the two legs may then differ.
* A `kLength` on `L1` (driving or reference) becomes a point–point `kDistance` from `A` to `P` with the same value and
  `reference` flag, and automatic placement (the old placement is dropped). The same for `L2` with `B`. So the overall
  size stays: a rectangle's width and height survive a chamfer of its corner.
* Other constraints on `L1` and `L2` stay (horizontal, vertical, parallel, perpendicular, angle, tangency).
* Rejected (false, unchanged) when `L1` or `L2` is in a `kEqual` (equal lengths would pull the shortened line back).
* Degrees of freedom do not change: `P1`, `P2` add four, the two `kOnCurve` and the two legs remove four.
* The result must solve (`kSolved` with the commit step), otherwise the whole command fails and nothing changes.
* Constraint IDs are retained when converting lengths, so existing dimension selections remain valid. Changes are
  transactional, including allocation failure; failed edits consume no IDs in the supplied sketch.

== Tool (`ToolSession`), controller and QML
* `Tool::kChamfer` ("Фаска", icon `chamfer.svg`), name `chamfer`, rail button `tool_chamfer` after `tool_extend`.
* Staged interaction (approved 28 October 2026): choose the first line, choose the second line, set the equal
  setback with the existing keypad, inspect the dashed preview, then confirm with “Готово” or Enter.
  The two lines must share one existing topological corner under the core rules above; crossing unconnected lines,
  arcs, circles, the same line twice and unsupported corners are rejected. Invalid second picks retain the first.
* Selected lines are highlighted. Persistent prompts read “Выберите первый отрезок”, “Выберите второй отрезок”,
  and “Задайте отступ и подтвердите”. The distance chip appears only after both lines are chosen.
  No geometry, constraints, IDs, revision or history change before explicit confirmation. While this tool is active,
  canvas presses select its lines instead of editing or dragging dimension labels whose touch targets overlap them.
* `InputField::kDistance` becomes active after both lines are chosen. `enter_value(d)` updates only the staged
  distance and preview. Finite positive distances are required. A geometrically too-long distance clears the preview,
  explains the rejection and disables confirmation, while retaining the pair so a smaller distance can repair it.
  Default 2 mm; the last entered distance is retained across tool changes within the session.
* Hover after selection never retargets the chosen corner. Extra canvas taps while the pair is staged do not commit
  or replace it. A successful `finish()` runs one transactional “Chamfer” command, clears the staged selection and
  returns to the first-line prompt. A solver rejection rolls back and retains the staged pair for retry or cancellation.
* Esc or “Отмена”, tool switching and reset discard all staged picks and preview without changing the sketch.
  Undo/Redo discard staged state before operating on committed history, following existing ToolSession behavior.
* Controller properties `chamfer_step` (`first`, `second`, `distance`, or empty for other tools) and `can_finish`
  drive the prompts and confirmation. Existing constraint/delete actions are not offered for staged chamfer picks.
* Error keys include `chamfer_pick_line`, `chamfer_not_corner`, `chamfer_too_long`, `chamfer_collinear`,
  `chamfer_equal_length`, `invalid_value`, and `chamfer_failed`; QML translates them. Solver rejection uses the
  existing solver-status message. Clearing a rejection after correction or cancellation also hides its toast, so an
  obsolete error cannot remain over a successful preview/result. Help describes the staged workflow, equal setbacks
  and cancellation.
* The distance chip retains its filled surface background, border and pencil mark. Typing a digit when distance
  input is active opens the keypad; accepting the keypad changes the preview and still requires “Готово” or Enter.

== Tablet preview sizing (approved 31 October 2026)

Issue: https://github.com/Artem535/SketchCAD/issues/58[#58].

After the two lines are chosen, show both equal setback dimensions on the canvas using the existing live dimension
style. Each has a minimum 48 px tap target. Tapping either opens the existing keypad for the same equal setback;
accepting it refreshes the preview without committing. The filled distance chip remains available, including when a
numerically entered setback is too long. Cancelling the keypad leaves the staged pair intact.

A dedicated `chamferHandle` has a 56 × 56 px target, a visible grip and a leader to the chamfer midpoint. Its centre is
64 screen px beyond that midpoint along the corner bisector, bounded inside the viewport so the finger does not cover
the chamfer. It appears only for a valid staged preview. Mouse, stylus and single-finger drag resize the preview even
when the general finger mode pans the canvas. Dragging the grip must not pan the viewport, move existing geometry,
start a committed gesture, edit committed dimensions, consume document IDs or add history. Dragging elsewhere retains
normal pan behavior. Pinch/zoom and view changes refresh the dimensions, grip and leader in screen coordinates.

The Qt-free tool consumes finite world-coordinate drag deltas. Project the delta onto the midpoint's path
`v = (u1 + u2) / 2`, with unit incident-line directions from the chosen corner, so `delta_distance = dot(delta, v) /
dot(v, v)`. Both offsets stay equal, including oblique corners. Clamp drag sizes to a positive nondegenerate setback
below the shorter adjacent line; moving back from a limit responds immediately. Invalid/nonfinite deltas and calls
without a valid pair do nothing. Numeric input retains its existing explicit too-long error rather than clamping.
Both setback values and the chip update during dragging. Release ends only the drag; Done/Enter still commits one
transaction and one Undo step. Cancel, reset, tool changes and successful finish remove live dimensions, grip and
leader together. Existing dimension manipulation outside this tool remains unchanged.
