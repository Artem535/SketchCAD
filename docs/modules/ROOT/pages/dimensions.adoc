= S02: Driving dimensions
:toc:

Issue: https://github.com/Artem535/SketchCAD/issues/7[#7]. Requirement: S01-DIM.
Depends on S01 (xref:constraint-solver.adoc[]) and C02 (xref:document-commands.adoc[]).

Driving dimensions are constraints with a value: they drive geometry through the same transactional solver.
Core stays Qt-free; the Qt bridge is `SketchController`. Not in this increment: dimension glyphs and the numeric
editor in QML (U02), reference (driven) dimensions, drag with soft preferences (U03), DOF display (S03), persistence.

The stage-0 `Rectangle` prototype (issue #1) is retired here: its acceptance scenario (50 × 30 mm rectangle,
origin anchor, rejected contradictory width, non-finite input) is re-expressed as a general-solver test,
and `rectangle.h/.cpp` with `rectangle_test` are removed.

== Model
New `ConstraintKind` values `kLength`, `kDistance`, `kAngle`, `kRadius`; `Constraint` gains `value` and `side`.

* `add_dimension(kind, first, second, value)` validates references and value and returns the ID, or `nullopt`
  without changing the sketch or allocator. `add_constraint` rejects dimension kinds and `add_dimension` rejects
  the geometric ones.
* `set_dimension(id, value)` changes the value of an existing dimension after the same value check; it returns false
  and changes nothing for unknown IDs, non-dimension constraints and invalid values. It does not solve:
  run it inside a `Document` command with `solver_step()` so an impossible value is rolled back with its history.
* `measure(sketch, kind, first, second)` (`solver.h`) returns the current value for valid references, so a dimension
  can be created at the present geometry.
* Dimensions are constraints: they share IDs, block erasing referenced entities, and are covered by snapshots,
  equality, Undo/Redo and rollback.

=== Kinds, references and values
Lengths are millimetres, angles radians in core.

[cols="1,2,1,3"]
|===
|Kind |References |Valid value |Hard residual

|`kLength` |line |finite, > 0 |\|d\| − v [mm]
|`kDistance` |point, point (distinct) |finite, > 0 |\|q − p\| − v [mm]. Zero distance is `kCoincident`.
|`kDistance` |point, line (either order, stored point first) |finite, ≥ 0 |side · signed distance to the infinite line − v [mm].
`side` (±1) is the side of the line the point is on at creation (+1 if on the line), so the residual stays smooth at v = 0.
|`kAngle` |line, line (distinct) |finite, 0 < v < π |Undirected angle error: ½ · atan2(sin 2φ, cos 2φ) with φ = θ − v,
θ the counter-clockwise angle from line 1 to line 2 [rad]. Lines at θ and θ + π satisfy the same dimension.
0 and π are parallelism, which is a constraint, not a dimension.
|`kRadius` |circle or arc |finite, > 0 |r − v [mm]
|===

Length residuals use the length tolerance (1e-7 mm), angles the angular tolerance (1e-9 rad).
Undefined residuals are `kInvalidInput` before solving, as in S01: a zero-length line in a length, angle or
point–line distance, and coincident points in a point–point distance.

`measure` returns: line length; point–point distance; unsigned point–line distance; the undirected angle in [0, π);
the radius. It returns `nullopt` for invalid references or undefined geometry.

== Tool integration
* Delete in `ToolSession` removes, in the same single command, the constraints and dimensions that reference
  the deleted entity and those of defining points that are erased with it; points kept because other geometry uses
  them keep their constraints. One Undo restores geometry and constraints.
* The point drag gesture solves after every step when the solver is installed; without stabilization the free DOF may
  jump. Smooth constrained drag is U03.

== Qt bridge (`SketchController`)
* Installs the solver as the document commit step; the last solve status is kept for messages.
* `add_dimension(kind, first, second)`: kinds `"length"`, `"distance"`, `"angle"`, `"radius"`; created at the measured
  value as one undo step; returns the ID, or 0 with message `invalid_dimension`.
* `set_dimension(id, value)`: one undo step. Angles are degrees in the bridge. Failure messages:
  `invalid_value` (value check), `conflict` (`kUnsatisfied`), `invalid_geometry` (`kInvalidInput`),
  `numerical_failure`. On failure geometry, dimensions and Undo state stay as before.
* `dimensions`: list of `{id, kind, value}` (angles in degrees), updated with `changed`.
* Messages are translation keys; visible text is U02.

== Acceptance / test cases
Core (`dimension_test`):

* Each kind: valid references accepted; zero/negative/NaN/∞ and out-of-range values rejected where invalid
  (point–line distance accepts 0); wrong references rejected atomically; `set_dimension` validates the same way.
* Each kind drives geometry: after a value change in a `Document` command with the solver, an independent oracle
  measures the new value within tolerance; one Undo restores the previous geometry and value.
* Each kind has an impossible value against fixed geometry that fails, keeping geometry, value and history.
* Angle: 90° from 0° (perpendicular start) and both orientations solve; point–line distance 0 puts the point on the line.
* Prototype scenario: rectangle with H/V sides, lengths 50 × 30 mm and fixed origin; width changes to 70;
  an extra contradictory width of 60 mm is rejected; non-finite input rejected.
* `measure` returns expected values and `nullopt` for invalid references.
* Delete cascade: deleting a constrained line removes its constraints and those of its erased endpoints in one undo step.

Qt (`sketch_controller_test`): `add_dimension` on a drawn line, `set_dimension` changes geometry and publishes
`dimensions` and `changed`; invalid value, conflict and invalid kind set the message and leave document and Undo
state unchanged; Undo restores the previous value.

All existing CTest checks stay green; desktop only.
