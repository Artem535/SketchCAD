= F02 implementation plan
:toc:

For agentic workers: use `superpowers:executing-plans` for inline execution or
`superpowers:subagent-driven-development` if the user selects delegated execution.
Follow the tasks in order; read xref:autosave-recovery.adoc[] and xref:project-format.adoc[] before implementing.

Goal:: Recover the last complete automatic checkpoint after a process crash, by explicit user choice,
without ever overwriting the user's project file.
Architecture:: A Qt-free committed-state accessor, recovery envelope codec and checkpoint schedule in the core;
a Qt recovery store (app-local directory, per-session QLockFile, QSaveFile); a recovery coordinator that
observes committed changes and integrates with the F01 `ProjectSession` file commands; a QML recovery list.
Stack:: C++20, reflect-cpp/yyjson (already a private core dependency), Qt Core/Quick/Test, GoogleTest.
Spec:: xref:autosave-recovery.adoc[]. Issue #14. Design approved by the user on 21 October 2026.
Status:: Implemented and locally verified on 21 October 2026; see the
xref:autosave-recovery.adoc#_execution_record_21_october_2026[execution record].

== Global constraints

* Debounce 5 s after the last committed change; at most 30 s from the first not-yet-checkpointed change;
  retry 30 s after a storage failure. Injectable clock; no writes for view-only events or unchanged state.
* Checkpoint only committed state with the live allocator watermark; never cancel or read an active gesture.
* Storage root `QStandardPaths::AppLocalDataLocation/recovery` with application name `SketchCAD`; tests and
  smoke use an injected root and never touch real recovery data.
* One random session UUID, one recovery file and one QLockFile (`setStaleLockTime(0)`, `tryLock(0)`) per
  running app; never remove a live owner's lock; never follow paths from metadata.
* Envelope v1: `format` = `SketchCADRecovery`, `version` = 1, `session_id`, `generation` (canonical uint64
  string, no wrap), `captured_at` (UTC), `original_url` (informational), `project_json` (F01 payload).
  Strict fields; 128 MiB envelope, F01 limits for the payload, nesting depth 16.
* QSaveFile with direct-write fallback disabled; failures keep the previous complete envelope.
* Restore is explicit, produces a dirty untitled document («Восстановлено — <name>») whose first save is Save As.
* No age/quota deletion; no Undo persistence; no cloud; no Android or power-loss claim.
* Google C++ style, snake_case, `Refs #14` commits; RED/GREEN evidence in the spec execution record and #14.
* Prefix shell commands with `rtk`; build in `build/fedora` (Release) and `build/fedora-werror` (Debug, `-Werror`).

== Review focus

* A drag in progress must never reach a checkpoint, and a checkpoint must never change dirty/Undo state (task 1, 5).
* A corrupt envelope or payload must never replace a valid document or be offered for restore (tasks 2, 6).
* A live instance's recovery is never listed, adopted, retired or deleted by another instance (task 4).
* A failed or cancelled Save/Open/Close keeps the recovery; cleanup failure blocks close and replacement (task 6).
* A restored copy is never written to `original_url` and survives a second crash before the next checkpoint (tasks 6, 7).

 public:
  static constexpr std::int64_t kDebounceMs = 5000;
  static constexpr std::int64_t kMaxDelayMs = 30000;

Interfaces produced (namespace `recovery`):

[source,cpp]
----
enum class Status { kValid, kInvalid, kUnsupported, kTooLarge, kUnreadable };
enum class Error { kStorage, kLocked, kMissing, kInvalid };
struct Candidate {
  QString session_id;
  QDateTime captured_at;      // invalid when unreadable
  QString original_url;       // informational
  Status status;
};
using WriterFactory = std::function<std::unique_ptr<project_file::detail::AtomicWriter>()>;
class Store {
 public:
  explicit Store(QString root, WriterFactory = {});
  static QString default_root();            // AppLocalDataLocation + "/recovery"
  bool start();                             // mkpath, new UUID, hold <uuid>.lock
  QString session_id() const;
  bool has_checkpoint() const;              // own <uuid>.sketchcad-recovery exists
  std::optional<Error> write(const sketchcad::ProjectData&, const QUrl& original);
  std::optional<Error> retire();            // delete own file, keep lock
  void release();                           // unlock and remove own lock (file untouched)
  std::vector<Candidate> discover() const;  // inactive sessions only, never own
  std::variant<sketchcad::RecoveryData, Error> claim(const QString& session_id);
  std::optional<Error> adopt();             // claimed session becomes own; old own file/lock retired
  std::optional<Error> discard_claim();     // delete claimed file + its temp files, release its lock
  void drop_claim();                        // release without changes
};
----

Rules: filenames are `<uuid>.sketchcad-recovery` and `<uuid>.lock` directly in the root; discovery accepts only
regular non-symlink files whose basename passes `valid_session_id` and whose envelope `session_id` matches.
Generation continues from the adopted/last written value and refuses to wrap. Reads are bounded by
`kRecoveryMaxBytes`. `claim` takes the lock with `tryLock(0)`, then rereads and validates the file.

== Deviations during implementation

* The coordinator takes `std::unique_ptr<recovery::Store>` (QLockFile is not movable) and its options are
  the namespace-level `RecoveryOptions` (GCC rejects a defaulted nested aggregate argument).
* `ProjectSession::recovery_source()` supplies `original_url`; `RecoveryCoordinator::installed(bool)` marks
  a document replacement instead of a separate epoch signal.
* `Store::start()` also removes stale locks of dead sessions without a checkpoint (see the execution record).
